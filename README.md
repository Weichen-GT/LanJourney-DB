# LanJourney-DB

Everything about the LanJourney PostgreSQL database (Supabase in prod, Docker locally).

| Path | What it is |
|---|---|
| [`schema.sql`](schema.sql) | **The schema** -- the single source of truth: tables, indexes, triggers, Row Level Security, the vocabulary-size tiers. Safe to re-run. |
| [`SCHEMA.md`](SCHEMA.md) | Readable reference of every table, column, key and index (generated from `schema.sql`). |
| [`reset.sql`](reset.sql) | **Wipe and rebuild**: drops every table, then recreates the empty schema (generated from `schema.sql`). |
| [`seed/`](seed) | **The vocabulary**, loaded in numeric order after the schema (generated by LanJourney-lib). |
| `migrations/` | Hand-run changes for databases that already exist (there is no migration runner; the backend uses `ddl-auto=validate`). Already folded into `schema.sql`. |
| `updates/` | In-place data fixes already applied to prod, kept as a record. |
| `archive/` | Superseded SQL. |
| `tools/` | `build_reset.py`, `gen_schema_doc.py` (below); `test_migration.sh` (tries a migration on throwaway databases: the `main` schema, a prod-like copy, and the current schema, plus re-runs). |

## Seed files (`seed/`)

| File | Contents |
|---|---|
| `01_vocabulary_original.sql` | The original 6,841 words and their meanings |
| `02_vocabulary_wordnet.sql` | The 3,143 WordNet-sourced words and their meanings |
| `03_vocabulary_expansion.sql` | 1,083 more common words (go, limit, injury, ...) and 2,060 meanings; fills the empty columns of a word that already exists as a stub row, skips colliding meanings |
| `04_frequency_rank.sql` | Sets `frequency_rank` for all ~11k words (must run last, after `03`) |

Result: 11,067 ranked words, 22,041 meanings. Each file is safe to re-run.

## Rebuild a database from scratch

Local Docker (from the LanJourney2.0 repo): `docker compose down -v && docker compose up -d` -- it loads
`schema.sql` and the four seed files automatically, in order.

Any other database (a staging project, a fresh local one), with `psql`:

```bash
psql "$DATABASE_URL" -f reset.sql            # DELETES everything, recreates the empty schema
psql "$DATABASE_URL" -f seed/01_vocabulary_original.sql
psql "$DATABASE_URL" -f seed/02_vocabulary_wordnet.sql
psql "$DATABASE_URL" -f seed/03_vocabulary_expansion.sql
psql "$DATABASE_URL" -f seed/04_frequency_rank.sql
```

`reset.sql` can be pasted into the Supabase SQL editor too, but the seed files are too large for it; use `psql`.
**Never run `reset.sql` on prod** -- it deletes every user and all progress.

## When you change things

- **Changed the schema:** edit `schema.sql` only, then
  `python tools/build_reset.py` and `python tools/gen_schema_doc.py` (needs the PostgreSQL binaries; it uses a
  throwaway local server), and commit the three files together. For a database that already exists, also add a
  hand-run script to `migrations/`.
- **Changed the vocabulary:** regenerate the seed files with the LanJourney-lib pipeline (its README), and for
  prod add an in-place script to `updates/` -- never reload meanings once real users exist (it cascades to their progress).
